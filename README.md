# Datatransp website

Astro static website with Vercel serverless contact forms.

## Development

Requires Node.js 22.12.0 or newer.

```sh
npm install
npm run dev
npm run typecheck
```

Create a local `.env` using `.env.example` when testing email delivery through a Vercel-compatible local runtime. Never commit `.env` or publish SMTP credentials.

Regenerate the true vector version of the approved Fama logo with `npm run vectorize:fama`. The resulting SVG contains vector paths rather than an embedded PNG.

## Production deployment

Deploy the project root to Vercel. The static pages are generated by `npm run build`; `api/contact.ts` is the serverless endpoint used by both contact forms.

For local end-to-end testing of the serverless form endpoint, use the Vercel CLI's `vercel dev` runtime with the local environment configured; Astro's static preview does not execute Vercel functions.

Set these values in the Vercel project environment settings:

- `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`
- `CONTACT_FROM` (optional; defaults to `SMTP_USER`)
- `CONTACT_TO` (optional; defaults to `comercial@datatransp.com.br`)

The contact endpoint returns an explicit service-unavailable response until SMTP is configured. Verify delivery with a test request after setting production credentials. The endpoint uses an in-memory per-instance rate limit, same-origin checks, field validation, consent confirmation, and a honeypot; for deployments that require a global rate limit, add a persistent shared rate-limiting service.
